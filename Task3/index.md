# Задание 3. Оценка Data Encryption at Rest and In Transit

Разделение данных по состоянию:

| Состояние | Описание | Где проявляется в системе Med |
|-----------|----------|-------------------------------|
| **At Rest (при хранении)** | Данные на носителях: диски серверов, БД, файловые хранилища, бэкапы, озеро данных | БД приложений (PostgreSQL), файловый сервер (Excel, PDF, сканы), 1С (файловая БД), озеро данных, Data Catalog |
| **In Transit (при передаче)** | Данные в движении между узлами: клиент–сервер, сервер–БД, система–внешняя система | HTTPS-сессии пользователей, API между сервисами, JDBC к БД, интеграция с лабораторией, ККМ–1С, платёжный провайдер, почта |
|

Классификация данных, обоснование необходимости защиты и предлагаемые инструменты защиты:

| Данные | В чём необходимость защиты | Инструменты защиты |
|----------------|----------------------------|---------------------|
| Идентификационные ПДн (Ф.И.О., дата рождения, СНИЛС, паспорт) | 152-ФЗ; прямая идентификация личности при утечке; риски мошенничества и дискриминации | Шифрование на уровне СУБД (TDE — Transparent Data Encryption) для БД; Шифрование на уровне диска/тома (FDE - Full Disk Encryption); KMS; TLS при передаче; RBAC; аудит доступа; маскирование в логах и отчётах |
| Контактные ПДн (телефон, e-mail) | 152-ФЗ; риски спама, фишинга, раскрытия контактов | Шифрование at rest (TDE/FDE); TLS in transit; минимизация в API; обфускация в логах |
| Расширенная анкета (адрес, место работы/учёбы) | 152-ФЗ; повышенная чувствительность; раскрытие образа жизни | Шифрование at rest; отдельный раздел/схема с усиленным доступом; TLS; не передавать в API партнёров |
| Медицинские данные (диагнозы, заключения, медкарты) | Медтайна, 152-ФЗ; репутационные и правовые риски; уголовная ответственность | Обязательное шифрование (TDE + при необходимости полевое); изоляция хранилища; TLS; только авторизованные каналы; полный аудит; DLP |
| Результаты исследований | Медтайна, 152-ФЗ; привязка к личности и состоянию здоровья | Шифрование at rest; привязка по идентификатору, не по Ф.И.О. в открытом виде; API с минимизацией ПДн, TLS |
| Платёжные данные (суммы, даты, привязка к пациенту) | 152-ФЗ; финансовая конфиденциальность; мошенничество | Шифрование в БД; TLS для ККМ–1С и платёжного провайдера; разграничение доступа; аудит; маскирование в отчётах |
| Кадровые и зарплатные данные | 152-ФЗ; защита ПДн сотрудников | Шифрование at rest; доступ только ролям бухгалтерии/кадров; TLS внутренних каналов; аудит |
| Операционные данные (журналы по ID, номенклатура) | Базовый уровень ИБ; косвенная идентификация при комбинировании | Шифрование томов; TLS между сервисами; доступ по ролям; базовый аудит |
|
